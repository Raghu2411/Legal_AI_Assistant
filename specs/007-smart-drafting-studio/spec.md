## User Scenarios & Testing *(mandatory)*
### User Story 1 - Client-Contextual Drafting Initiation (Priority: P1)

As a Lawyer, I want to select a client, a specific document type (e.g., NDA), a document name, and up to 3 precedent documents before starting a drafting session so that the session is initialized with the correct context and metadata.

**Why this priority**: Essential for data integrity and meeting Constitution Principle XXVI.

**Independent Test**: Verify that drafting cannot start without selecting both a client and a document type, and that precedent selection is available.

**Acceptance Scenarios**:

1. **Given** a lawyer is on the Drafting page, **When** no client or document type is selected, **Then** the "Start Drafting" button is disabled.
2. **Given** a lawyer selects a client, "NDA", and 1 precedent document, **When** they click "Start Drafting", **Then** the studio opens with all selected context loaded.

---

### User Story 2 - Interactive AI-Assisted Interview (Priority: P1)

As a Lawyer, I want the AI to guide me through a series of questions so that the document is built progressively based on my specific needs.

**Why this priority**: Core functionality of the drafting studio (Constitution Principle XXVII).

**Independent Test**: Start an interview and verify that AI questions result in new text fragments appearing in the editor upon user response.

**Acceptance Scenarios**:

1. **Given** a new drafting session, **When** the AI asks a question about the document content, **Then** after I provide a response, the editor is updated with a corresponding clause.

---

### User Story 3 - Manual Editor Sovereignty (Priority: P2)

As a Lawyer, I want to manually edit any part of the document at any time so that I have final control over the legal language.

**Why this priority**: Required by Constitution Principle XXVIII.

**Independent Test**: Verify that text generated by AI can be directly modified or deleted in the rich text editor.

**Acceptance Scenarios**:

1. **Given** an AI-generated clause in the editor, **When** I manually change the text, **Then** the manual change is preserved and not overwritten by subsequent AI actions.

---

### User Story 4 - Finalization, Storage & RAG Indexing (Priority: P2)

As a Lawyer, I want to save the finalized document so that it is stored securely and indexed for future AI retrieval.

**Why this priority**: Ensures document persistence and enables future search (Constitution Principle XXIX).

**Independent Test**: Save a document and verify its presence in the storage system and document logs, then check if its content is retrievable via search.

**Acceptance Scenarios**:

1. **Given** a completed draft, **When** I click "Finalize & Save", **Then** the document is generated and uploaded to the secure storage bucket.
2. **Given** a saved document, **When** I search the system, **Then** the content of this document is retrievable by the AI.

---

### User Story 5 - Professional Cover Email Generation (Priority: P3)

As a Lawyer, I want to generate a cover email based on the drafted document so that I can quickly prepare the document for transmission to the client.

**Why this priority**: Streamlines the delivery process (Constitution Principle XXX).

**Independent Test**: Click 'Draft Email' and verify the generated text reflects the document's subject and client context.

**Acceptance Scenarios**:

1. **Given** a saved draft, **When** I click "Draft Email", **Then** a professional email draft appears using the document content as context.

### Edge Cases

- **Session Interruption**: If the browser is closed or refreshed mid-interview, the current interview state and unsaved editor content are lost. (Decision: In-memory/Session Only for MVP).
- **Empty Responses**: If a user skips a question or provides an "unknown" response, the AI MUST insert a highlighted placeholder (e.g., `[MISSING_TERM]`) and proceed to the next question.
- **Concurrent Edits**: To prevent race conditions, the rich text editor MUST be locked for manual input while the AI is actively streaming or generating a text fragment (Option A).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST require a client selection and a document type selection (from a predefined list) before entering the drafting studio.
- **FR-002**: System MUST display Client Name, Case ID, and Case Type in the studio interface.
- **FR-003**: System MUST provide a two-column layout: Left column for the AI chat interview and Right column for the rich text document editor.
- **FR-004**: System MUST maintain the state of the interview conversation and the current document draft during the session.
- **FR-005**: AI MUST generate document fragments that are inserted into the editor in response to the interview.
- **FR-006**: System MUST automatically index saved documents into the vector database.
- **FR-007**: System MUST provide an explicit "Draft Email" action to generate a cover letter.
- **FR-008**: System MUST save finalized documents to the designated storage bucket.
- **FR-009**: System MUST log document metadata in the central documents table.
- **FR-010**: System MUST initialize the AI interview state based on the selected document type template.
- **FR-011**: System MUST lock the rich text editor for manual input while an AI text generation operation is in progress.
- **FR-012**: System MUST allow users to define a custom document name, pre-filled with a system-suggested default.
- **FR-013**: System MUST allow users to select 1-3 precedent documents from the Client's Vault to provide context for the AI drafting logic.
- **FR-014**: System MUST insert highlighted placeholders for missing information when a user skips an interview question.

### Key Entities *(include if feature involves data)*

- **DraftSession**: Temporary state for the active interview (metadata, conversation history, selected precedents).
- **Document**: The final output record linked to a client and stored in system storage.
- **Client**: Source of metadata (fetched from client records).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Lawyers can initiate a new draft in under 5 seconds after client selection.
- **SC-002**: AI-generated fragments appear in the editor within 2 seconds of a user response.
- **SC-003**: 100% of saved documents are successfully indexed and searchable.
- **SC-004**: Manual edits are never lost or overwritten by AI updates.

## Assumptions

- **A-001**: The AI interview logic is stateful within the current session.
- **A-002**: 'Draft Email' utility provides text only and does not handle actual transmission.
- **A-003**: Document finalization converts the editor content into a standard document format (e.g., PDF/DOCX).
